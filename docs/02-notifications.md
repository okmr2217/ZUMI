# ZUMI（済） - 通知

> 関連: [用語定義](./01-glossary.md) / [Duty管理・記録・振り返り・アカウント](./03-duty-log-review-account.md) / [技術スタック・インフラ](./05-tech-stack.md)

## 3-1. 通知

| 種別 | 内容 |
|---|---|
| 朝の日次まとめ | 今日の対象 Duty をまとめて通知。ユーザーが送信時刻を設定 |
| 締め切りアラート | 未完了 Duty があれば夜に通知。ユーザーが送信時刻を設定 |
| 前夜通知（Duty 単位・任意） | 「ゴミは前の晩に出す」など、当日朝では間に合わない Duty のみ個別にオン |
| 週次サマリー | 週の達成率とシェア用カードを通知。送るのは週の最終日（週の始まりが月曜なら日曜）に固定で、時刻だけを設定する |

### 設計方針

- 通知の総量を増やさないことを最優先とする。Duty 単位の個別時刻通知は持たせず、朝夜のまとめに集約する
- 朝のまとめに対象がゼロの場合は送らない（無通知を許容する）
- 期日不確定型の扱い: `SINCE_LAST` は催促が発生している Duty のみ、`WEEKLY_COUNT` は「週の残回数 ≥ 残り日数（今日を含む）」になった時点から通知に含める。「上回った」時点ではもう週内に達成できないため、「以上」とする
- 週次サマリーの曜日を自由に選べるようにすると、「どの週をまとめるか」が曖昧になる。そのため曜日は週の最終日に固定する。週の始まりはユーザー設定（[期日計算の境界ルール](./03-duty-log-review-account.md#期日計算の境界ルール202611-確定)）
- 通知チャネルは Web Push を基本とするが、**iOS の Web Push は「ホーム画面に追加」が前提**という重大な制約がある。日本のユーザー基盤を考えると LINE 通知のほうが到達率が高いため、以下の優先度で実装する
  1. Web Push（VAPID）: 無料プラン込み。Android・PC ブラウザに加え、iOS はホーム画面に追加した場合のみ
  2. メール（Resend 等）: フォールバック（v1.1）
  3. LINE Messaging API: 有料プランの目玉機能
- **iOS への対応（2026/11 確定）**: MVP ではメールでの代わりの通知は入れない。その代わり、オンボーディングでホーム画面への追加を案内する。また、通知が未許可なら今日タブ上部のバナーで許可を促す（[オンボーディング](./03-duty-log-review-account.md#オンボーディング202611-再設計)）

### 通知の文面

Web Push は展開前だとタイトル＋1〜2行しか見えないため、要点（件数と Duty 名）をタイトルと本文の先頭に置く。Duty のアイコンは本文には入れず、通知アイコンにはアプリのアイコンを使う。

| 種別 | タイトル | 本文 | タップ時 |
|---|---|---|---|
| 朝の日次まとめ | 今日の Duty 3件 | ゴミ出し（可燃）・プロテイン・お風呂（そろそろ） | 今日タブ |
| 締め切りアラート | まだ済んでいないもの 2件 | プロテイン・英語学習（あと1回・日曜まで） | 今日タブ |
| 週次サマリー | 今週は 18/20 | 先週より +3。シェア用のカードができています | 振り返りタブ |

- 本文は「今日」「そろそろ」「今週」の順に Duty 名を「・」でつなぐ。長い場合は「ほか N件」で省略する
- 締め切りアラートでは、スキップしたものと済んだものは除く
- 「催促」はバックエンド用語なので、文面では使わない（[用語定義](./01-glossary.md)）

通知配信の技術的な設計（Cron Trigger のスケジューリング方式など）は [技術スタック・インフラ](./05-tech-stack.md) を参照。

# ZUMI（済） - プロダクト概要

> 最終更新: 2026/08 ／ 前身: Habito 要件定義
> 関連: [用語定義](./01-glossary.md) / [Duty管理・記録・振り返り・アカウント](./03-duty-log-review-account.md) / [画面構成](./04-screens.md)

定期的な義務的な活動をリマインド・記録するアプリ。

## 対象となる活動

- ゴミ出し: 曜日が決まっている
- 英語学習: 週1回などの目標を立てて管理したい
- 風呂: 私は毎日入るのが当たり前ではないので管理したい
- プロテインやサプリの摂取: 毎日摂るようにしたい

---

## 1. プロダクト概要

| 項目 | 内容 |
|---|---|
| アプリ名 | ZUMI（済） |
| コンセプト | 「やりたいこと」ではなく「やらなきゃいけないこと」だけを扱う、義務専用のリマインド＆記録アプリ |
| コア体験 | 「済」の朱印をワンタップで押す。書くことはない |
| 主指標 | 週単位の達成率（連続記録／ストリークは扱わない） |
| ターゲット | 一人暮らしを始めて生活の運用が回っていない20〜30代 |
| プラットフォーム | Web アプリ（Next.js / PWA） |
| マネタイズ | 無料スタート、将来的にサブスク（Pro） |
| 認証 | メールアドレス＋パスワード（better-auth） |

既存の習慣化アプリは「なりたい自分」に向かうための道具で、連続記録が途切れた瞬間に人を責めます。しかしゴミ出しも風呂もプロテインも、自己実現ではなく生活を最低限回すための作業です。ZUMI はここだけに絞り、途切れても翌週から普通に再開できる設計にします。

完了操作は「済」の朱印を押すこと。名前・操作・記録・シェア画像がすべて同じビジュアルモチーフで統一されます。

### 基本的な利用フロー

1. **オンボーディング**: テンプレート（ゴミ出し／風呂／サプリ／学習／シーツ交換 など）から選ぶだけで Duty を登録。自由入力は後回しにして初回の離脱を防ぐ
2. **繰り返しルールを設定**: 毎日／曜日指定／週N回／間隔ベース など
3. **朝の通知**: 今日やるべき Duty がまとめて1通で届く
4. **記録**: 済んだらワンタップで「済」。テキスト入力は一切なし
5. **夜の通知**: 未完了があれば締め切りアラート。寝落ち前に回収する
6. **週次サマリー**: 週の達成率と朱印の並んだカードが届く。そのままシェア画像として保存・投稿できる

### ターゲットユーザー

**プライマリ: 20〜30代の単身生活者**

- 一人暮らしを始めて日が浅く、生活の運用がまだ回っていない
- 「うっかり忘れ」「先延ばし」の自覚があり、覚えていること自体に消耗している
- カレンダーやリマインダーアプリは使っているが、繰り返しタスクが他の予定に埋もれる／通知を消して終わってしまう
- 習慣化アプリを一度は試したが、意識の高さと自分の温度が合わずに続かなかった

**セカンダリ: 同居人・家族と分担がある人**

- ゴミ出しや掃除の当番が曖昧なまま、言った言わないになっている
- （課金機能「共有 Duty」の対象）

### 想定される活動（テンプレート候補）

オンボーディングのテンプレート一覧に含める活動候補。既存例（ゴミ出し／英語学習／風呂／プロテイン・サプリ／シーツ交換）に加えて以下を追加する。

| 活動 | 想定タイプ |
|---|---|
| 水回り（排水口・換気扇）掃除 | `SINCE_LAST` |
| 掃除機がけ | `SINCE_LAST` または `WEEKLY_COUNT` |
| エアコンフィルター掃除 | `MONTHLY` |
| コンタクトレンズケース交換 | `SINCE_LAST` |
| 常備薬・救急箱の在庫確認 | `MONTHLY` |
| サブスク・固定費の見直し | `MONTHLY`（隔月は `NTH_WEEK` 相当の月次版だが v1では毎月に丸める） |
| 実家・家族への連絡 | `WEEKLY_COUNT` |
| 観葉植物・ペット用品の管理 | `WEEKDAYS` または `SINCE_LAST` |

特に `SINCE_LAST` は水回り・コンタクトケースなど「サボりがちだが起点固定だと破綻する」活動と相性がよく、テンプレートを拡充する価値が高い。

**対象外とする活動（設計上の判断）**: 車検・健康診断・保険更新のような年1回の義務は、現行スキーマに `YEARLY` がなく対象外とする。これは意図的な線引きであり、「週単位の達成率」がコアの成立条件になっているアプリの性質上、年次イベントを含めるとコンセプトが薄まる。年次のリマインドはGoogleカレンダー等の役割として明確に切り分け、ヘルプ文言で「年に数回のイベントはカレンダーへ、繰り返す生活の作業はZUMIへ」と住み分けを案内する。

### ユーザー獲得（LP）の訴求ポイント

主訴求は **「習慣アプリ、続かなかった人へ」**。競合との対比を最初に置き、自己啓発文脈から明確に距離を取ります。

| 訴求 | コピー案 |
|---|---|
| 三日坊主を責めない | 連続記録は数えません。週で「だいたい済んだ」が見えれば十分 |
| 通知疲れしない | 1日2通だけ。朝に今日の分をまとめて、夜に未完了だけ |
| 記録コストがゼロ | 書くことはありません。押すだけ |
| 対象が生活そのもの | ゴミ出しも、風呂も、プロテインも、同じ場所で |
| 変な周期に対応 | 「隔週の資源ゴミ」「最後にやってから3日空いたら」も設定できる |
| シェア | 今週の「済」を1枚の画像に。未達も含めて出せる |

CTA は「無料で始める」。LP 内に週次サマリーカードの実物を大きく置き、それ自体を広告素材として機能させます。

### デザイン方針

コア体験が「朱印をワンタップで押す」ことである以上、デザインの軸はここに一極集中させる。

| 方針 | 内容 |
|---|---|
| モチーフ | 判子・朱肉を全体のビジュアルモチーフとして統一。ベースは白〜生成り色、差し色は朱色一色に絞る |
| トーン | 既存の習慣化アプリが多用する多色バッジ・炎アイコン・グラデーションは避け、事務的で落ち着いたトーンにする。「役所の書類仕事を淡々と処理する」感覚を狙う |
| 押印アニメーション | プロダクト唯一のコアインタラクションとして最も投資する。朱印がわずかに斜めにズレて押される、軽いハプティクスが入る、といった「本物の判子らしさ」の再現を優先する |
| 情報密度 | 「覚えていること自体に消耗している」ユーザーが対象のため、低密度を保つ。特に「今日」タブは進捗バーとDuty一覧のみに絞り、統計的な情報は「振り返り」タブに寄せる |
| タイポグラフィ | 全体はゴシックで実務的に。「済」の文字だけ手書き・篆書風の質感を持たせ、判子らしさを強調する |

シェア画像（[振り返り・シェア](./03-duty-log-review-account.md#3-4-振り返りシェア)）・押印アニメーション・LP のビジュアルは、すべてこの「判子」モチーフで一貫させる。

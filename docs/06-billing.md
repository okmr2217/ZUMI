## 6. 課金

無料でスタートするが、将来的にサブスクプランを導入することを目標とする。

| | 無料 | Pro（¥300〜500 / 月 想定） |
|---|---|---|
| Duty 数 | 5件まで | 無制限 |
| 通知 | Web Push / メール | LINE 通知を追加 |
| 履歴保持 | 直近3ヶ月 | 無制限 |
| シェアカード | 標準テーマ | テーマ選択・カスタマイズ |
| 共有 Duty | — | 同居人・家族と当番を共有 |

### 課金設計の考え方

- 無料枠の制限は「Duty 数」に置く。最も自然に上限に当たる軸であり、かつ生活が回り始めてから当たるため、価値を実感した後に課金判断が来る
- LINE 通知は原価（Messaging API の送信数）が乗るため、有料側に置く合理性が説明しやすい
- 履歴3ヶ月制限は D1 のサイズ上限対策も兼ねる
- 「共有 Duty」は単価ではなくユーザー数を増やす機能。招待された同居人が新規ユーザーになる導線として、獲得施策も兼ねる

### MVPでのスコープ

MVP時点では**無料プランの制約ロジック（Duty5件上限・履歴3ヶ月）のみ実装し、決済導線・決済連携は持たない**。課金機能が追加されるまでは、全ユーザーが無料プランの制約下で（Pro向けの解放や決済誘導なしに）利用する。Stripe等の決済連携・Proプラン管理・アップグレードUIはv1.1以降に回す。理由: MVPの目的はコア体験（繰り返しタイプ6種＋シェア導線）の検証であり、初期ユーザー数が少ない段階で課金基盤に工数を割く優先度は低い。タスクの詳細分解は [09-implementation-tasks.md](./09-implementation-tasks.md) を参照。
